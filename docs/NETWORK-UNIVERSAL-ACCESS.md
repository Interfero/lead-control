# Универсальный доступ к CRM и сервисам (VPN / белые списки / без VPN)

**Цель:** `https://lead-control.space` открывается всегда — с VPN, без VPN, в режиме «белых списков» у оператора.

**Prod:** VPS `194.67.92.69`, приложение `/var/www/lead-control`, CRM по пути `/crm/`.

---

## Почему «то работает, то нет»

Три режима **конфликтуют**, если нет единой схемы:

| Режим | Что происходит | Почему CRM падает |
|-------|----------------|-------------------|
| **VPN включён** | Весь трафик через туннель (Хельсинки и т.д.) | Путь до `194.67.92.69` часто **обрывает большие ответы** (~16 KB+) |
| **Белые списки (VPN оператора)** | Работают только **домены из списка** | Скрипты с `hosts` → прямой IP **в обход списка** → сайт не грузится |
| **Без VPN** | Прямой доступ к IP VPS | Обычно OK, но нестабильно у части провайдеров |

Раньше ставили **локальные костыли** (`deploy/fix-lead-control-vpn-lag.ps1` / `.sh`): маршрут + hosts на IP VPS. Они **помогают только с обычным VPN** и **ломают белые списки**. Отсюда ощущение «вечной рулетки».

**Сервер и код CRM здесь ни при чём** — с VPS страницы отдаются за доли секунды. Проблема в **том, как браузер доходит до сервера**.

---

## Универсальное решение (один раз)

```text
Браузер / телефон
    → DNS: lead-control.space
    → IP Cloudflare (edge, ближайший узел)
    → HTTPS → origin VPS 194.67.92.69
    → nginx + PHP (CRM, Desk, API)
```

### Шаг 1 — Cloudflare Proxy ON (главное)

Аккаунт и NS уже на Cloudflare. Осталось включить прокси:

1. [dash.cloudflare.com](https://dash.cloudflare.com) → `lead-control.space` → **DNS**
2. Записи **A** `@` и `www` → `194.67.92.69`
3. **Proxy status** → **Proxied** (оранжевое облако), не «DNS only»
4. **SSL/TLS** → **Full (strict)** (на VPS уже Let's Encrypt)
5. **Always Use HTTPS** → On

Через 5–15 минут:

```powershell
powershell -ExecutionPolicy Bypass -File deploy\check-network-mode.ps1
```

Ожидание: DNS A — **не** `194.67.92.69`, в ответе есть заголовок `cf-ray`.

Детали: `docs/CLOUDFLARE.md`.

### Шаг 2 — Убрать локальные обходы у всех, кто ставил

**Windows (от админа):**

```powershell
powershell -ExecutionPolicy Bypass -File deploy\fix-lead-control-vpn-lag.ps1 -Uninstall
```

**macOS:**

```bash
sudo bash deploy/fix-lead-control-vpn-lag.sh uninstall
```

После Cloudflare эти скрипты **вредят**, особенно при белых списках.

### Шаг 3 — Правила для сотрудников

1. Заходить только по **`https://lead-control.space/crm/`** (или `/crm/login`), **не по IP**
2. Не править `hosts` на `194.67.92.69`
3. При «не грузится»: Ctrl+F5, другой браузер; **не** включать обход-VPN скрипты
4. В Chrome/Яндекс при странных DNS: «Защищённый DNS» можно выключить (не обязательно с CF)

### Шаг 4 — Белые списки (организационно)

Если оператор даёт режим «только разрешённые сайты»:

- В списке должен быть домен **`lead-control.space`** (не IP)
- С **оранжевым облаком** CF пользователь всё равно обращается к **домену** — это совместимо со списками
- **Hosts на IP** — несовместимо; шаг 2 обязателен

Добавление домена в список у оператора — через ваш VPN/IT, не через код CRM.

## Что уже готово на сервере

- nginx: SSL, gzip, кэш статики `/crm/build`, `/crm/css`, `/crm/js`
- MTU 1280, `tcp_mtu_probing` (защита от PMTU blackhole на origin)
- `include cloudflare-realip.conf` — реальный IP клиента для логов и rate limit
- Laravel: `trustProxies(at: '*')`, сессии не привязаны к IP при смене VPN
- Все ассеты CRM — **с того же домена**, без внешних CDN

Отдельный временный «прокси на shared» (`enable-shared-https-proxy.sh`) **сейчас не используется**.

## Чего не существует

- **Магической настройки в Laravel**, которая обойдёт блокировку IP у VPN или оператора
- **Одного скрипта на всех ПК**, который одновременно починит и VPN, и белые списки — они требуют **противоположного** маршрутизации
- **100% гарантии** без домена в белом списке оператора в период жёстких ограничений — но с CF + домен в списке это стандартная рабочая схема

## Откат

Cloudflare DNS → Proxy **DNS only** (серое облако). Снова прямой IP и старые проблемы с VPN.
