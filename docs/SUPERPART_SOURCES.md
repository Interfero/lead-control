# SuperPart: справочник источников и привязка к заказу

Документ для разработчиков приложения SuperPart: как получать список источников из CRM, назначать партнёра на источник и передавать выбранный источник при создании заявки.

## Аутентификация (как у остальных методов v1)

Все запросы к `https://<домен-CRM>/api/v1/...` (кроме случаев пустого ключа в dev):

| Заголовок | Значение |
|-----------|----------|
| `X-API-Key` | `SUPERPART_API_KEY` из `.env` CRM |
| `X-Signature` | `hash_hmac('sha256', <сырое тело запроса>, SUPERPART_API_SECRET)` — для **GET** тело пустое, подпись считается от пустой строки |
| `Content-Type` | `application/json` для методов с телом |

Идемпотентность **POST /partner-orders** — без изменений: обязателен заголовок `Idempotency-Key`.

## Настройка в CRM

- В карточке источника (**Управление → Источники заказов**) включается флаг **«Показывать в каталоге SuperPart»** (`available_for_superpart`). Только такие **активные** источники попадают в `GET /reference/sources`.
- Поле **ID партнёра SuperPart** в CRM **не редактируется вручную**; его обновляет SuperPart через **PATCH** (см. ниже).

## 1. Список источников для UI

**Запрос:** `GET /api/v1/reference/sources`

**Ответ 200:**

```json
{
  "data": [
    {
      "source_id": 12,
      "source_name": "Листовки",
      "city_id": 1,
      "city_name": "Москва",
      "superpart_partner_id": 42
    }
  ]
}
```

`superpart_partner_id` может быть `null` (источник **общий** — доступен любому партнёру из списка) или число (источник **закреплён** за партнёром с этим `user_id` в SuperPart).

**Рекомендация по UI:** при отображении списка заявки показывать только те строки, где `superpart_partner_id` совпадает с текущим пользователем-партнёром **или** `superpart_partner_id === null`.

## 2. Назначение / снятие партнёра на источнике

**Запрос:** `PATCH /api/v1/reference/sources/{source_id}`

Тело JSON **обязано содержать ключ** `superpart_partner_id`:

- число ≥ 1 — закрепить источник за партнёром;
- `null` — снять закрепление (источник снова общий).

Пример закрепления:

```json
{
  "superpart_partner_id": 42
}
```

Пример снятия:

```json
{
  "superpart_partner_id": null
}
```

**Ошибки:**

| Код | Причина |
|-----|---------|
| 404 | Нет источника с таким `source_id` |
| 422 | Источник не в каталоге SuperPart (`available_for_superpart = false`) |
| 422 | Валидация тела (нет ключа `superpart_partner_id`, неверный тип) |

Подпись `X-Signature` для PATCH считается от **точной** JSON-строки тела (как его отправляет клиент).

## 3. Создание заявки с выбранным источником

**Запрос:** `POST /api/v1/partner-orders` (прежние поля + опционально `source_id`).

- **`source_id`** (integer, опционально): идентификатор из справочника. Если **не передан**, CRM использует резервный источник из `.env` (`SUPERPART_DEFAULT_SOURCE_ID`) — для поэтапного внедрения старых клиентов SuperPart.
- Если **`source_id` передан**, CRM проверяет: источник существует, активен, включён в каталог SuperPart; если у источника задан `superpart_partner_id`, он **должен совпадать** с **`partner_user_id`** в том же запросе.

При ошибке проверки источника API вернёт **422** с полем ошибок (например `source_id`).

## Порядок внедрения

1. В CRM отметить нужные источники флагом «Показывать в каталоге SuperPart».
2. В SuperPart: загрузить список `GET /reference/sources`, показать выбор при создании заявки (с фильтрацией по `superpart_partner_id` как выше).
3. Реализовать в админке SuperPart вызов `PATCH .../sources/{id}` при назначении гендиректором партнёра на канал.
4. В `POST /partner-orders` начать передавать `source_id`; после полного перехода можно отказаться от единственного `SUPERPART_DEFAULT_SOURCE_ID` в пользу обязательного поля (решение на стороне продуктов).
