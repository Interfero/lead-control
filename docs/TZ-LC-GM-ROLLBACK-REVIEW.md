# ТЗ: откат «Проверки», закрытие из гильдии сразу в «Готов»

**Кому:** Стёпа (Lead Control)  
**От:** команда GM (repair-guild.ru)  
**Дата:** 2026-09-14  
**Приоритет:** блокер  
**Префикс:** `https://lead-control.space/api/v1/gm`  
**Авторизация:** Bearer + `X-GM-User-Id` / Email / Login  

Проверка: **#578**, мастер **#112** Тбилиси.

---

Вчера из‑за 500 в ENUM добавили статус `review` («Проверка»), и `POST …/review` из кабинета стал туда ставить заявку. **До этого такого статуса в вебе не было.** Убираем.

Проверка закрытия — только в гильдии. CRM сразу **«Готов»** (`completed`): касса, суммы, расчёт. Второго круга в LC нет.

## Метод (тот же)

`POST /api/v1/gm/orders/{id}/review`  
тело как сейчас: `{ amountPaidRub, amountCompRub, masterComment }`  
заголовки **мастера** заявки.

| Откуда | Куда |
|--------|------|
| `in_progress` | `completed` («Готов») |
| `in_progress_sd` | `completed` («Готов») |
| `review` (вчерашние, в т.ч. **#578**) | `completed` («Готов»), **не 409** |

Новые закрытия статус `review` **не ставят**. Повтор на уже Готов → **409**.

В ответе 2xx и в следующем `GET` — `status: "completed"` и `financialSnapshot`:

- взято / ЗПЧ / чистыми / ЗП мастера (`masterSalaryRub`)
- `orderCore`: `core` = категория **А**, `non_core` = **Б**

Как кнопка «Готов» в вебе до вчерашнего фикса.

## Приёмка

1. Закрытие из работы или СД → сразу Готов, в JSON есть snapshot (суммы, ЗП, `orderCore`).
2. #578 и остальные `review` → Готов.
3. Повтор на Готов → 409.
4. В кабинете после закрытия — расчёт и А/Б, в CRM нет «Проверки».
